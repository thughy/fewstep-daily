结论先行第一层 · 框架

结论： 复核后换了两篇。最终 3 篇是 DMAD（替换 FastH3 Omni）、One-Forcing（替换 AGF）和 Lost in the Rollout / LiveTalk（保留）。三篇说的其实是同一件事：光靠 DMD 的 score 差不够，真实数据、教师样本和初始化这三样东西决定了少步学生的上限。

换掉哪两篇、为什么（两句话）：

  • FastH3 Omni → DMAD。 两者底座都是 H3，但 FastH3 是技术发布，不是论文，而且没有任何质量数字。DMAD 在 H3 上有人评、AVGen-Bench 和完整训练代码，每次生成器更新的时间还只有 DMD2 的 29%（233 s vs 818 s）。按我们自己的评级，它本来就高一档（必读·先跑 vs 值得读）。FastH3 里有用的两处（按模态分开归一化、音视频用不同 shift），我并进了 DMAD 一节和跨篇的 AV 线。
  • AGF → One-Forcing。 AGF 在 5 s 上没有增益（82.03 vs SF 82.21）。60 s 以内比它的底座 SGF 高 1.8，但去掉正则就反而低于 SGF，各部件都没有单独的证据。One-Forcing 有干净的单部件消融：只加 GAN 头，1 步从 75.27 涨到 80.36。它会改变的是「流式学生要几步、要不要接真实数据判别头」这个决定，代码 + 权重齐全，Wan 1.3B 上训练约 1 小时。

对我们训练的含义（先看这三条）：

  1. H3 AV 的 critic 选型可以零训练先比一次。 DMAD 的 H3 LoRA 已公开，用推理把 DMAD、FastH3 和 H3 教师放在同一批 prompt 上比，重点看同步：DMAD 的 AV-sync 是 49.1，DMD2 是 56.7原文 表6，这是它唯一明显的短板。
  2. 流式学生先测「DMD + 真实数据 GAN 头」，再谈降到 1 步。 One-Forcing 里 GAN 头这一项就值 +5.09 VBench。它的 GAN 权重只有 0.03，接到我们现有的 Self-Forcing 式 DMD 上改动很小【代码 model/one_forcing.py:407】。
  3. 图像或参考条件的 AV 蒸馏，先把条件质检和初始化做对，再调 DMD。 LiveTalk 只把 ODE 初始化从 4k 步训到 20k 步，FID 就从 14.90 降到 11.67，Sync-C 从 3.53 升到 4.15，是整条配方里最大的一个旋钮原文 表3。OR 版在 H3 上加了音频能量辅助目标，Sync-C 从 7.37 升到 8.02【仅OR】，正好可以补 DMAD 的同步短板。

DMAD L3，梯度上等价于 L2：判别器 logit 的梯度就是 score 差。目标是「教师 × 真实数据」的几何混合 学生随机步数回放（on-policy）+ 离线教师样本 + 真实 AV 数据；训练时不在线调用教师 一个 critic 主干（H3 LoRA，第 49 块特征），两个头；音频、视频 token 分开平均后再 1:1 合并 单步去噪 × AV（双向 H3，4 步）

① DMAD：判别器的 logit 就是 DMD 梯度，H3 上可直接换 critic（必读·先跑）

一句话

DMD2 要两个 score 网络（教师 real score 和持续拟合的 fake score）做差。DMAD 证明了一点：一个训到最优的二分类判别器，它的 logit 对输入的梯度正好就是这个 score 差。所以 critic 只需要判别，不用拟合 score，教师也不用在线调用。再加一个「真实数据 vs 学生」的头，目标就从「教师分布」变成「教师 × 真实数据」原文 Prop.1、式 1–4、附录 A。

H3 上的关键操作（以代码为准，train/h3/lightx2v_train/trainers/dmd/minimax_h3_dmad_trainer.py）

  1. 准备数据（离线一次）： UltraVideo 的真实片段编码成 AV latent，共 24,005 条，124 帧的有 17,912 条。每条 caption 用 H3 教师跑 31 步 Euler 生成一个教师样本，shift 用 video 12 / audio 3。处理好的数据约 300 GB，已公开在 HF（有许可门槛）【代码 README:76-90；data_process/gen_teacher_data.py:42-44】。
  2. 学生生成 G： 4 步学生做 backward simulation，随机停在第 1–4 步。中间噪声级在 U[0.02, 0.98] 上随机抽，再按模态分别 shift（video 12、audio 2）。只有最后一次前向带梯度【代码 minimax_h3_trainer.py:122-141；dmad_trainer.py:341-342】。
  3. 加噪： G、真实样本 T、教师样本 Q 共用同一组 (σ_v, σ_a)，噪声各自独立抽。σ_a < σ_v：base u=0.5 时 σ_v 0.923，σ_a 0.667【代码 dmad_trainer.py:343-345, 360-366；我测】。
  4. critic 打分： 第二份 H3（LoRA rank 128）跑到第 49 块就截断，特征先做无仿射 RMSNorm，再接两个 MLP 头 d_real 和 d_teacher。音频 token 和视频 token 各自求均值，再 1:1 平均。注释里写明：直接对所有 token 求平均的话，结果约 99% 来自视频【代码 dmad_trainer.py:262-295】。按发布配置算，音频行只占 414/(414+37,296) ≈ 1.1%我测，Codex✓。
  5. critic loss（4 项 BCE）： softplus(d_t(G)) + softplus(d_r(G)) + softplus(−d_t(Q)) + softplus(−d_r(T))，不做任何 score 回归【代码 dmad_trainer.py:368】。
  6. 生成器 loss： −d_r(G) − (w_gap/E[w])·d_t(G)，critic 冻结、梯度只经过输入。w_gap 按 10 个噪声段的 EMA 计算：真实头越能分开「真实 vs 教师」的噪声段，教师项的权重越低【代码 dmad_trainer.py:347-356, 305-328】。
  7. 更新： 学生和 critic 1:1 交替，lr 4e-5，不做梯度裁剪；论文 checkpoint 是第 800 步的 EMA 权重。8×H200 上每 100 步约 6.7 h，所以 800 步约 430 H200·h【代码 README:15-20；我测：按 README 推算】。

因果逻辑（带数字）

  • 最优 logit 的梯度 = s_target − s_θ，所以不需要两个 score 网络相减，critic 也不必跟踪学生分布的 score。所以 H3 上每次生成器更新只要 233.3 s，DMD2 要 818.1 s（4×H200；DMD2 是 5:1 更新），显存也从 127.2 降到 114.7 GiB原文 表5。
  • 加上真实头之后，目标变成 M ∝ p_T^ρ · p_R^(1−ρ)原文 附录 A。所以学生能被拉向「比教师更真实」。证据：AVGen Visual 93.3，比教师的 92.6 还高；去掉真实头后 SDXL 的 FID 从 14.47 变成 21.37（教师 cfg6 是 19.36）原文 表6、表4、表2。
  • 只看平均 logit，管不到局部的音画对齐推断。证据：AV-sync 49.1，低于 DMD2 的 56.7 和教师的 58.3；但 Lip 30.6 高于 DMD2 的 22.7（教师 39.0）。也就是同步类指标一升一降，不是全面变差原文 表6。

  • H3 上的 DMD2 和 rCM 是作者自己复现的，没有种子方差，也没有同一 prompt 多种子的多样性测量原文 附录 B。
  • 等价性需要「判别器不受限、训到最优」。H3 的 critic 是 LoRA，而且截断在第 49 块，不满足这个条件，所以实际训练出来的东西只是近似 DMD原文 附录 A；代码；推断。
  • Wan 的代码里生成器和 critic 各有一半 block 加了谱归一化，论文没写；H3 的 trainer 里没有代码 train/wan/.../t2v_model_distill_dmad.py:488；Codex✓。
  • 造教师样本时 audio shift 用 3，训练和推理用 2，论文没解释【代码 gen_teacher_data.py:44 vs configs/dmad_minimax_h3.yaml】。
  • README 说 full_critic 版（第 1600 步）在 AVGen 上分数更高，但没给数字【代码 README:132】。

对我们 H3 训练的含义 + 第一个对照

  • 它改变的决定： H3 AV 少步用什么 critic，DMD2 式 score 差，还是 DMAD 式双头判别。外加一个工程规则：任何作用在 AV 联合 token 上的 loss 或 logit，都要按模态分开平均或归一化。否则音频只占约 1% 的权重【代码 + 我测】。
  • 第一个对照（零训练，只做推理）： 同一批 H3 评测 prompt，每条 4 个种子，分 5 臂：H3 教师 50 步、DMAD lora_critic、DMAD full_critic、FastH3 4 步 LoRA、FastH3 8 步（如果我们有自己的 DMD2 学生，加第 6 臂）。测 SyncNet LSE-C/D（原始值，不用 VLM 打分）、WER（Whisper）、ffmpeg 响度和声道、FD-DINOv2 或 VBench、同一 prompt 下的 LPIPS 多样性。

② One-Forcing：流式 1 步，要靠真实数据 GAN 头和 ODE 初始化（必读·先跑）

一句话

Self-Forcing 降到 1 步会变糊（77.18）。One-Forcing 在 DMD 上加了一个很轻的真实视频判别头（权重 0.03），并把自回归粒度从 3 帧一块改成逐帧，1 步就做到 83.76。但这个数字包含 FFE（第 1 帧走 4 步）；去掉 FFE 是 80.69原文 表1、表4。

关键操作（以代码为准，Aurora-edu/One-Forcing @c9a2350）

  1. 初始化： 因果 Wan 1.3B，用 Causal Forcing 的因果 ODE checkpoint。教师是 14B 双向模型（冻结），fake score 是 1.3B 双向（可训）原文 §3.3；代码 config.yaml。
  2. 生成器步（每 5 步一次）： 逐帧自回归，每帧 1 步（denoising_step_list: [1000]）。每生成一帧，用 t=0 再前向一次写 KV，这一次不带梯度。21 帧都参与打分，只有最后 17 帧回传梯度【代码 config.yaml:29-31；pipeline/self_forcing_training.py:139】。
  3. DMD 项： 整段 rollout 共用一个 t（shift 5，范围 [20, 980]）。梯度是 (x̂_fake − x̂_real) 除以 |x − x̂_real| 的均值（默认 p_real_l1）。教师 guidance 5，写法是 C + 5(C − U)，等效 CFG 6；fake score 不加 CFG【代码 model/dmd.py:42, 120-134】。
  4. GAN 项： 把同一段 rollout 独立加噪，送进 fake score 主干，取第 21、29 层特征。每层接一个 learned register 做 cross-attention，再过 MLP 得到一个整段级的 logit。生成器 loss = DMD + 0.03·softplus(−D(G))【代码 model/one_forcing.py:249, 407；config.yaml:85-92】。
  5. critic 步（每步都做）： fake score 做扩散回归，判别头做 softplus(−D(real)) + softplus(D(G))。真实视频和学生 rollout 用同一个 t、同一份噪声加噪【代码 model/one_forcing.py:333, 535】。逐帧配置不需要 R1/R2；chunkwise 配置要 R1 1.0 / R2 0.001【代码 config.yaml:93-94；chunkwise_config.yaml:83】。
  6. 规模： 200 次迭代（生成器只更新 40 次），8×H100 约 1 h，即约 8 GPU·h。真实数据是 mixkit 清单，6,484 条代码 README；Codex✓：这是推算，论文没写数据规模。

因果逻辑（带数字）

  • 所以要加一个直接看真实视频的信号。证据：同初始化、同 200 步，只加 GAN 头，Total 从 75.27 到 80.36，Quality 从 78.29 到 83.22，Multiple objects 从 39.41 到 65.24原文 表4a。recall 从 0.457 升到 0.711，但 LPIPS 多样性没变（0.6437 vs 0.6440）原文 附录 H。也就是覆盖更全了，单个 prompt 内的多样性没有变化。

③ Lost in the Rollout / LiveTalk：参考图同时进了两边打分，ODE 初始化是最大的旋钮（必读·先跑）

一句话

在参考图条件的 AV avatar 上做 Self-Forcing DMD，几百步就会塌成黑帧或糊帧。原因是参考图直接进了教师和 critic 的打分输入，参考图本身的缺陷会被双方同时当成「对的」。修法不改 loss：只改数据（条件质检）、初始化（ODE 训到收敛）和步长（LR 和 CFG）。OR 版再加一项：让生成音频的能量对齐教师样本，在 H3 上 Sync-C 从 7.37 升到 8.02原文 LiveTalk §3；仅OR。

  2. 参考图进入模型的两条路：

跨篇：这一周真正的认知变化

1. 真实数据或判别项要显式回到 DMD

  • DMAD：去掉真实头，SDXL FID 从 14.47 到 21.37，比教师还差；One-Forcing：去掉 GAN 头，1 步从 80.36 到 75.27原文。两个都是同配置下的单部件消融，而且在两个完全不同的设置里（双向 4 步、流式 1 步）方向一致。
  • 区别在于真实数据的地位：DMAD 让判别器成为主梯度，One-Forcing 只把它当作 0.03 的辅助项。对我们来说，先试 0.03 辅助项的风险更低；如果效果够好，再考虑整体换成 DMAD推断。

2. 「离线教师样本」回来了

DMD2 把对教师样本的回归去掉了。本周的两篇又把它请了回来，形式都不是逐样本回归：DMAD 用它做判别正样本，Lost 用它算音频能量这个统计量原文 + 仅OR。好处是学生的目标里重新有了「教师整体长什么样」，而不只是逐点 score。

3. 初始化决定少步学生的上限

One-Forcing：ODE 初始化 vs CD 初始化，Dynamic 52.76 vs 23.61；LiveTalk：ODE 训 4k vs 20k 步，FID 14.90 vs 11.67。这两条都比后面 DMD 阶段任何一个超参的影响大原文。同一条线上的还有 Drift Forcing（初始化换成自 rollout 漂移场，仅OR）。对我们来说，流式学生先审一遍初始化，比调 DMD 超参划算推断。

4. AV：音频必须单独照顾

  • H3 上三份公开代码都让音频走更低的噪声：DMAD 训练时 audio shift 2，造教师样本时用 3；FastH3 是 3；视频都是 12【代码】。所以「τ_a ≠ τ_v」本身就是 H3 的默认做法，真正要扫的是 audio shift 的取值（2、3 和 12，最后一个就是对称加噪）推断。
  • 在 token 层面，DMAD 按模态平均 logit，FastH3 按模态归一化 DMD 梯度。不这样做，音频只占约 1% 的权重【代码 + 我测】。
  • 同步是目前 H3 少步的共同短板：DMAD 的 AV-sync 49.1，比 DMD2 低；补法候选有音频能量项（Lost，仅OR）和局部 AV 判别头（推断）。MDD 和 MAAD（仅OR）也指向同一个方向。

放不进框架的

  • FastH3 Omni：不是论文，是可用的 H3 训练栈（PDD + DMD2，约 7,800 GPU·h，数据不公开）。它的价值在于给对照实验当参照，不在机制。等它出现同协议的质量数字，当天复评。
  • LiveTalk 的首帧标签： 干净的参考帧顶着一个带噪的时间步标签进入打分。这是一个「条件 vs 噪声级」不一致的输入，论文没讨论它对 critic 的影响代码；推断。

推荐跑的顺序

  1. DMAD / FastH3 / 教师的推理比较（零训练，几十 GPU·h）：决定 H3 少步基线用谁，并量出同步短板有多大。
  2. 流式学生 + 0.03 真实 AV 判别头（One-Forcing 的思路，3 臂）：先验证判别头本身，再谈降步。
  3. H3 音频能量项 2 臂（Lost OR 版）：如果第 1 步确认了同步短板，就用它来补。
  4. DMD2 vs DMAD 训练对照（约 1,200 H200·h）：前三步都指向「换 critic 值得」时再跑。
  5. AGF 作为第 2 步的可叠加项保留：如果我们流式的主要问题是 10–60 s 的误差累积，再跑「AGF vs 同 ε 高斯 + 同正则」。
