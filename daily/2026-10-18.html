精读 · Speculative Forcing：结论

Speculative Forcing（2610.22347，KAIST + NAVER AI Lab）评级：必读·先跑。 原创性是新机制（中），可信度在效率–质量曲线上站得住，但 VBench 差距落在噪声内，代码也还没放出来。

  • 它做了什么：不改生成器的权重，把 4 步因果学生每一步的中间 x̂0 当成「草稿」，逐 token 判断草稿是否已经收敛。收敛的 token 当场定稿，不再去噪，它的 KV 留给其余 token 注意；没收敛的继续去噪。每个 chunk 生成完后，用 t=0 的干净前向刷新整块 KV 缓存。
  • 为什么值得先跑：它是我目前见到的第一个在等吞吐下打赢「均匀少步」的逐 token 早停方法。3 天前读的 ForcingBooster（2610.12625）在 4 个底座里只赢了 1 个。在 Lingbot-World 2.0 上，它比均匀 3 步快（24.5 vs 22.8 fps），质量又不低于 4 步（Quality 82.65 vs 82.62，Drift 2.839 vs 3.094）原文 Tab.3。
  • 对我们训练的含义（一句话）：用 Self-Forcing 式「随机出口步」DMD 训出来的流式学生，中间步的 x̂0 本身就是被监督过的样本，所以这份加速几乎是免费的，而且训练无关版只需要标定两个阈值。反过来，如果我们换成只监督最后一步的目标（例如 causal rCM / 一致性类），这条路可能就断了。所以要先测一下自己学生的中间步 x̂0 质量。推断
  • 先跑的对照：在我们的 4 步流式学生上跑三组：训练无关 verifier（冗余度 + 稳定性），对照等墙钟（含 VAE）的均匀 2 步和 3 步，再加一个 oracle verifier 作上界。rollout 60 s，测漂移，至少 2 个种子。只花推理算力。

精读 · 细节

① 关键操作（逐步）
  1. 底座：冻结的 4 步因果学生（LongLive 1.3B、Lingbot-World 2.0 Causal-Fast 1.3B）。时间步沿用原调度 [1000, 937.5, 833.3, 625]。在第 k 步停下的 token，恰好走完这个调度的前 k 步，所以均匀 k 步基线用的是同一条前缀原文 App.A。
  2. 第 1 步：每个 token 都去噪一次，得到草稿 x̂0^(1)。
  3. 验证（每步 k<K，只验证仍然活跃的 token）：
    • 训练无关版：k=1 时算冗余度 s_red(i) = min_h‖x̂0^(1)(i) − h‖，h 取注意力窗口内历史 chunk、参考帧和 sink 里所有空间位置的干净 token；k≥2 时算稳定性 s_stab(i) = ‖x̂0^(k)(i) − x̂0^(k−1)(i)‖。分数先过一遍时空平滑 S（空间 9×9 高斯，σ=1 token；时间上对当前和后续潜帧做高斯平均），再和阈值 τ_red、τ_stab 比，低于阈值就接受原文 §3.3.1、App.A。
    • 学习版：取生成器最后一个 transformer block 的隐状态，过 LayerNorm 和三层 3D 卷积（1536→96→48→1），预测 r̂_k(i)，平滑后 ≤ε 就接受原文 §3.3.2、App.A。
  4. 定稿：被接受的 token 输出固定为 x̂0^(k)(i)，之后的前向不再计算它，但它在接受那一步的逐层 KV 保留，供活跃 token 注意。被拒绝的 token 重新加噪到下一个噪声级，继续去噪。到第 K 步还活跃的 token 一律定稿原文 §3.2。
  5. chunk 完成后：拼好的 c_t（各 token 来自不同步）再用 t=0 做一次干净前向，刷新整块 KV，后续 chunk 看到的历史统一来自干净输出原文 App.A。这一步把「混合步 KV」挡在了 chunk 内部。
  6. 学习版的训练（只训头）：冻结生成器跑满 K 步，收集中间隐状态和 oracle 差距 rel_k(i) = ‖x̂0^(k)(i) − x̂0^(K)(i)‖ / σ_t（σ_t 是该 chunk 满步输出 token 范数的中位数）。

等价形式：生成器侧没有 loss。verifier 的 loss 是 L(φ) = mean_{i,k<K} smoothL1(r̂_k(i), rel_k(i))（式 2）。推理规则是 k(i) = min{k : Sr̂_k ≤ ε}，找不到就取 K；输出 c_t(i) = x̂0^(k(i))(i)。也就是把 ‖x̂0^(k) − x̂0^(K)‖ 当作一个可以提前预测的「剩余去噪量」，在逐 token 上做早退出（early exit）。这一点和投机解码不同：投机解码的验证是无损的（拒绝采样保证分布不变），这里的验证是有损阈值，论文也说没有采用投机解码的接受规则原文 §2。

② 因果逻辑和数字例子
  • 因为：蒸馏后的少步学生在中间步就给出接近终点的 x̂0，而且不同 token 收敛速度差很多。和历史重复的背景收敛早，新出现的区域要走到最后（Fig.2）。所以：逐 token 早停能省掉大半 token 前向。证据：5 s LongLive 平均 1.68 步/token（4 步基线是 4.0）原文 Tab.1。
  • Amdahl 账（用原文吞吐反推，5 s LongLive，H100，不含 VAE）由原文 Tab.1/C 计算：
    • 每帧耗时：1 步 14.71 ms、2 步 22.45 ms、3 步 30.17 ms、4 步 37.88 ms。每多一步约 +7.73 ms，非常线性；和步数无关的固定部分约 6.98 ms，主要是干净刷新前向。
    • 照这个线性模型，k̄=1.68 应该是 6.98 + 1.68×7.73 ≈ 19.97 ms（约 50 fps，1.90×），和论文给的理想值 5/(k̄+1)=1.87× 一致。实测是 41.74 fps，即 23.96 ms（1.58×）。
    • 差出来的约 4.0 ms/帧（约半步），来自「chunk 要一直跑到最后一个活跃 token 被接受」：每一步都要付一次前向的固定开销，开销由 max_i k*(i) 决定，不由平均值决定原文 D.2，再加上 verifier 和 gather 的开销。
  • 等时间对比（这是关键证据）：
    • 5 s：均匀 2 步 44.54 fps、Total 82.46；OursH 41.74 fps、83.21。按耗时在 2 步和 3 步之间线性插值，同耗时的均匀基线约 82.58，OursH 高 +0.63。对 3 步（33.15 fps，83.08）是又快 26%、又高 0.13由原文计算。
    • 30 s：均匀 2 步 40.9 fps、82.32、Drift 1.992；OursH 37.8 fps、82.81、Drift 1.707原文 Tab.2。
    • 世界模型：均匀 3 步 22.8 fps、82.38、Drift 3.361；OursH 24.5 fps、82.65、Drift 2.839，速度和质量同时占优原文 Tab.3。
  • 逐 token vs 逐 chunk：用同一个 verifier，改成整个 chunk 一起接受，在相同平均步数（2.61）下 Quality 82.54、Drift 3.214，逐 token 是 82.65、2.839原文 Tab.5。所以粒度本身有贡献。不过两者的 Quality 只差 0.11。
  • verifier 准不准：学习版头的 AUROC 在 0.87–0.94，稳定性信号 0.71–0.89，冗余度 0.61–0.85，运动差分（MotionCache 式）0.54–0.72原文 Tab.A。oracle verifier 在 2.46 步时 Quality 82.61，学习版 82.65，已经到天花板原文 Tab.5。
③ 和最接近的工作差在哪里（只写操作上的差别）
工作 操作上的差别 改变了什么
ForcingBooster 2610.12625（我 10-13 读过；本文没比） 都冻结 4 步因果学生、逐 patch/token 早停、停掉的保留 KV。ForcingBooster 的路由器用「停止概率 × 质量误差 + 步数代价」做 on-policy 训练，目标是步数–质量的折中。本文 verifier 直接回归到满步输出的剩余差距，再加时空平滑，chunk 结束后干净前向刷新 KV，另外还有一个不用训练的版本 ForcingBooster 等时间下只在 1/4 个底座赢均匀 2 步；本文在 LongLive 和 Lingbot 上都赢等时间的均匀基线。差别具体来自哪一处没法确认，不同底座（Causal Forcing vs LongLive）也可能是原因推断

投机解码（Leviathan 2023 / Chen 2023） 大模型做无损验证，被拒绝的从验证点重采样。本文没有验证模型，用阈值做有损接受，被拒绝的只是多走一步 名字是类比，没有分布保持的保证
HSA / RAS / 缓存类 所有 token 都要走到调度终点，靠周期性全量更新压误差。本文的 token 会「定稿」，之后不再计算 被定稿的 token 不再有误差累积，代价是草稿错了就收不回来

⑦ 对我们训练的含义
模态 含义 先跑的对照
图像 无直接含义。少步图像学生（如 4 步 DMD2）没有历史冗余，只剩稳定性信号能用。注意力里已定稿的 token 照样要参与，所以省下的计算有限推断 无
纯视频（双向少步） 弱。没有 chunk 和 KV 的结构，定稿 token 每一步还要作为 KV 重新计算，除非缓存它推断 无
AV 有潜力。数字人背景和身体大部分静止（论文 D.3 自己也提了），视频 token 可以大量早停。风险在音频：如果视频 token 早定稿，嘴部区域的细化可能被截断，同步会受影响。音频 token 是否适用还不清楚推断 只对视频 token 开 verifier，音频 token 全步。测 LSE、Sync、嘴部区域 LPIPS 和 WER，对照等墙钟的均匀 2/3 步
流式 AR 直接可用，而且可能改变训练决定：①部署时用逐 token 早停替代「直接降到 2 步」；②训练侧，继续保留 Self-Forcing 的随机出口步 DMD 监督，因为它让中间 x̂0 可以直接当输出。换成只监督最后一步的目标前，先测中间 x̂0 在我们的 4 步流式学生上，训练无关 verifier（按 oracle ε=0.24 标定 τ）vs 等墙钟（含 VAE）的均匀 2 步、3 步 vs oracle 上界。60 s rollout，测 Drift、Dynamic、Aesthetic，至少 2 个种子

⑤ 精读 · Routed Forcing（必读·先跑）
  • 等价形式：d = x̂_fake(z_s) − [(1−A)·x̂_T(z_s) + A·x̂_T(z_r)]，其中 A = M_person·1[t≥τ]，z_r 是同一个 ε 加噪的条件匹配真实视频。从 SF 训练 1000 步的检查点出发，再训练 200 步。OmniAvatar-14B → LiveTalk-1.3B，4 步，块大小 3原文 §3–4。
