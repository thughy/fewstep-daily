① Matrix-Game 4.0：每 chunk 1–2 步的流式渲染器，蒸馏照搬 Causal Forcing++（重做·应用，可用资源）

结论：v1.4 (a)(b) 都不满足 → 不升先跑。(a) 训练代码没放（SkyworkAI/Matrix-Game/Matrix-Game-4 只有 matrix_game/inference/，最后提交 10-16 20:12 北京时间代码，sparse clone 实测）；(b) 没有任何质量对照。

关键操作原文 §4.3：

  1. 从 Wan2.2-Fun-5B Control 微调一个双向 v2v 渲染器：条件是 low-poly 代理视频 + 动态 caption + 最多 3 帧按相机位姿检索的空间记忆帧。
  2. Stage 1 因果 teacher：每个 latent 帧各自加噪，只看前面的干净真值帧，同样用 FM 损失，训 20k 步。
  3. Stage 2 因果 CD：在 48 级网格上，冻结的因果 teacher 带 CFG 3 走一步 Euler，到低一级；在线学生从高一级预测干净 chunk，去对齐 EMA 学生从低一级给的预测。5k 步后 EMA 学生能 4 步出一个 chunk。
  4. Stage 3 非对称 DMD：学生做自 rollout，长度在 21 / 41 / 61 / 121 个 latent 帧里抽，cache = 首帧 + 最近 20 帧；real score = 带 CFG 的冻结双向模型，fake score 在线训练，两个 score 都只评最后 21 帧。学生每 chunk 2 步，首帧 4 步；fake score 每步更新，学生每 5 步更新一次；跑 1,000 步。
  5. 部署对齐：学生 80% 的步吃 TAEHV 编码的控制，20% 吃 Wan-VAE 编码；两个 score 一直吃 Wan-VAE 编码。

因果逻辑：因为部署端为了速度把控制编码器换成了 TAEHV → 学生训练时要是只见过 Wan-VAE 编码，部署就会有输入偏移 → 所以把偏移放进学生输入，score 的输入不动，打分基准就不跟着漂。证据：论文没有做「去掉这一项」的消融，只是作为「最新配方」写进去的原文。

② PRIMFLOW：把「步内动力学」换成一个可学的累计位移原函数（值得看）

结论：L1 格里的参数化变体。证据只有一个复现基线加单种子，不改决定。

关键操作原文 §3.3–3.4；Codex✓ 盲分一致：

  1. 学生在步首做一次骨干前向得到特征 h；一个小分支（8 个门控残差块，25.8M 参数）输出原函数 P(τ)，表示从源点沿教师轨迹累计走了多远，并且构造上保证 P(源点) = 0。
  2. 训练时在 128 个子步里随机取跨 3 个子步的小窗，要求 [P(b) − P(a)]/(b − a) 等于教师在高噪声端点的速度。训练状态前 250 步由教师推进，之后逐步换成 detach 掉的学生推进。
  3. 推理时一步走完整个区间，位移 = P(终点) − P(起点)。
  4. Endpoint absorption：冻结带原函数分支的模型，只训原生输出头（norm + 投影）去拟合它的端点平均速度，然后丢掉分支，仍是 1 NFE。

因果逻辑：因为 ArcFlow / π-Flow / PDD 都事先规定了步内动力学的函数族或网格 → 函数族一错，局部监督就拼不出准确的全局位移 → PRIMFLOW 不规定函数族，直接学累计量，命题 1 用局部误差加 Lipschitz 项给全局误差上界 → 证据：T-FID 23.55 → 20.92，HPSv2 27.71 → 28.35原文 表1。

做法，一步一步：

  1. Stage 1：冻结 H3，训练一个控制 LoRA φ。结构视频走 H3 原生的 reference 通路，放在它描述的那几帧的位置上，不加类型标记。50 步采样能跟住结构，但画面偏糊。

  3. 只训加速 LoRA ψ，控制 LoRA φ 冻结。 学生四步生成，critic（fake score，rank-128 LoRA，从 teacher 初始化，每次学生更新前更新 5 次）给学生样本打分，teacher 是 Stage 1 的 50 步模型。

到底蒸了什么（关键操作，一步一步）

  1. 学生结构（PDD）：H3 的 transformer_ref 输出头从 1 个速度扩成 32 个 fine-grid 区间头；推理时按 4 个一组融合，得到 8 次前向（pdd_steps: 32，pdd_step_indices 0,4,…,32）【代码：dmpdd_ref2va.yaml；HF fastvideo_inference.json】。PDD 方法来自 NVIDIA FastGen 的 Parallel Decoding Distillation 2607.26004（read-log 里原评「值得读候选」）。
  2. DMD 那一路：每次学生前向，把剩下的所有头积分到干净端点，得到 x̂0（dmpdd.py:139–147），再对它做 DMD2：teacher（冻结 H3 ref2va，dense attention）和 critic（可训练 H3，dense）都在 x0 空间预测；teacher 和 critic 都做 CFG，guidance 都是 2.0，uncond = 文本 / presentation 置零、参考 latent 保留（packed_dmd.py:692–734；yaml real_score_guidance_scale / fake_score_guidance_scale: 2.0，cfg_uncond: text: zero）【代码】。
  3. 核心梯度（按模态分开）：对 video、audio 各自取切片，grad = (fake − real) / (mean|gen − real| + 1e-6)，loss_m = 0.5·MSE(gen, sg(gen − grad))，再按 modality_loss_weights（默认都是 1）相加（packed_dmd.py:754–764）【代码】。和 Self-Forcing model/dmd.py:113 一样是 fake − real，不同在于归一化分母按模态各算一次，所以 audio 的梯度量级不会被 video 吃掉。
  4. 打分时间（模态时钟）：先按 score_timestep_shift: 2.4 抽一个基础时间 u，然后 σ_v = shift₁₂(u)、σ_a = shift₃(u)（packed_dmd.py:466–483；minimax_h3_dmd.py:353–363；pdd.py:77–90）【代码】。算出来【我测】：u=0.25 → σ_v 0.63 / σ_a 0.29；u=0.5 → 0.83 / 0.56；u=0.75 → 0.94 / 0.79。也就是固定耦合的 τ_a < τ_v，不是独立采样，也没有消融。
  5. Critic：在学生 x̂0 上加噪后做 x0 回归（packed_dmd.py:565–604），条件 dropout 0.1，4 次 critic 更新配 1 次学生更新（generator_update_interval: 5）；学生做梯度裁剪 1.0，critic 不裁剪代码 / 原文 omniref_dmpdd.md。
  6. PDD 辅助项：随机挑一个窗口内的头，监督目标是教师在该区间上的 Euler 均值速度（teacher CFG 2.0），按模态分别算 MSE 再相加；学生总 loss = DMD + 0.3 × PDD（pdd.py:386–436；dmpdd.py:164–174）【代码】。
  7. 学生状态从哪来：公开 yaml 写的是 rollout_mode: data_latent，也就是把真实数据加噪到某个块起点，而不是 DMD2 那种 backward simulation；simulate 是可选模式（dmpdd.py:84–88）【代码】。发布的 checkpoint 实际用的是哪种模式，原文没写推断：Nuva 说「更多高质量数据」，大概率是 data_latent。
  8. 稀疏 + 规模：学生训练和推理都用 VSA（sparsity 0.9，tile 128，参考 token keep rate 0.1），teacher 和 critic 是 dense；64 张 B300、3,500 步、约 7,800 GPU 小时原文 博客。示例 yaml 是 8 卡 SP8 / FSDP8、lr 5e-6、1,000 步；数据（omni reference dataset，Nuva 整理）不公开代码 / 原文。

QAD（NVFP4）怎么做：只有 T2VA 的 FastH3-QAD-v2 卡片写了做法：学生用部署时的 NVFP4 W4A4（attention q/k/v/out 和 MLP 线性层），对着冻结的 BF16 8 步蒸馏模型自己作 teacher，沿 teacher 的 8 步轨迹训；只用文本 prompt，300 步，lr 5e-6，25% 的样本行走学生自己的轨迹；只训量化线性层，VSA gate 和 norm 冻结（改 gate 会改 attend 到哪些 tile）原文 HF 卡。结果只有一张表：30 个 held-out prompt 上 x0 预测相对 BF16 teacher 的相对 L2，均值 0.351（video 0.382、audio 0.319）原文；没有 PTQ（不训练直接量化）对照，也没有感知指标，所以 0.35 是好是坏无法判断推断。Omni 版的 QAD 卡片没有写任何训练细节或数字原文。H3 的 QAD 训练代码和 loss 仓库里没有，只有通用的 NVFP4 STE 线性层（nvfp4_qat_train_config.py）、推理和转换脚本，以及 Wan2.1 的 Attn-QAT + DMD2 示例代码，Codex 检索 + 我抽查。一个量化相关的实测数据：如果把 text / 参考 / 音频这段 attention prefix 也放进 FP4，同一段 480p 5 s 视频相对 bf16 attention 参考的 PSNR 从 25.26 掉到 20.96 dB，SSIM 从 0.852 掉到 0.785。所以发布配置把这段 prefix 留在 FP8 / bf16，代价是在 Spark 上多花约 24% 的去噪时间原文 docs/inference/fasth3_omniref.md。

对我们训练的含义（先跑的对照）
