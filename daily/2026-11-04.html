1. History Forcing（2611.02782）· 必读·先跑 (a)

History Forcing（2611.02782）· 必读·先跑 (a)

结论 / 对我们： 流式少步 DMD 应开一组对照——参考分是否加「有历史−无历史」AR teacher 残差。码+权重齐，先在 Wan2.1-1.3B 复现他们的 use_history_guidance。

白话背景。 少步 AR 视频蒸馏（DMD / on-policy 自蒸馏）主要盯当前 chunk 的分布匹配；长程里主体/场景离开又回来时，历史约束进不了参考分。

具体问题。 怎样把「更干净的历史」变成对当前预测的校正，同时保留双向教师的画质监督，而不是直接拿漂移更大的 AR 分布当目标？

方法逐步。

  1. 学生 on-policy rollout，取当前噪声 chunk。
  2. 历史对比：同一噪声输入与同一 timestep，冻结 AR teacher 各跑一遍——带额外历史 h / 不带；差分 = history residual。
  3. 长视频一致性：额外历史来自学生更早、漂移更少的 chunk；残差加到双向教师给出的 DMD s_ref（实现里是 x0 空间 pred_real + scale * delta）。
  4. Out-of-sight：额外历史来自固定视角教师 rollout（场景仍可见）；残差加到 OPSD 的 EMA 教师速度目标。

为什么可能成立。 残差只传递「历史引起的位移」，不把整个 AR 建模误差灌进目标；双向参考仍靠近数据分布。推断：与 CFG 形 guidance 同构

关键数字。原文 1.3B：VBench Quality 85.07（15s）；VBench-Long aggregate 79.82（60s）；PlayWorld Evolution 2.35→2.70；MemoBench Object Consistency 58.43→62.18。

限制。 我们未自跑同协议；OPSD 世界模型支路是 DreamX-World-5B，与 T2V 支路分开；AV 未测。

代码核验。【代码】 History-Forcing/dmd/model/dmd.py：_history_effect + history_guidance_scale；【HF】xzxxntxdy/History-Forcing（dmd/opsd/ar_teacher）。

taxonomy。Codex✓ L2（DMD）+ L1（OPSD 速度）+ L4。预判失效处：历史窗口选错或 λ 过大 → 动态度被钉死。推断

2. Disen-Forcing（2611.02822）· 值得读

Disen-Forcing（2611.02822）· 值得读

结论 / 对我们： frame sink 不能当「万能注意力锚」灌进所有头——在 DMD 上会把运动压向教师低动态模式。蒸馏期按锚头/工作头拆上下文，是值得做的插件对照；暂无独立训码 → 不升必读·先跑。

白话背景。 长 rollout 常用 frame sink 钉首帧；一致性升、动态度常掉。

具体问题。 首帧在 AR-VDM 里是不是 LLM 式 attention sink？若不是，统一 sink 是否造成蒸馏时运动塌缩？

方法逐步。

  1. 诊断：统计头级注意力——稀疏 anchor heads 管长程语义，多数 working heads 管局部运动。
  2. Disentangled context routing（蒸馏时）：仅锚头看初始帧 sink；其余只看滑动窗口。
  3. Motion-disentangling regularization：约束锚头不把全局语义泄漏进运动通路（反事实注意图匹配一类）。

为什么。 模式寻求的 DMD 下，全头暴露首帧 = 过条件化 → 塌向低方差近静态模式；拆路由对准已有头分工。

关键数字。原文 Self-Forcing→+Disen：短窗 Total 76.37→82.38，Dynamic 40.44→73.12，drift 7.23→4.03；长窗类似（74.75→82.34；Dynamic 34.70→73.95）。相对纯 Frame Sink：后者 Dynamic 可从 65 砸到 37。

限制。 项目页 disen-forcing.github.io；未见独立训练仓库（文中引用 Infinite-Forcing）；锚头识别一次性、底座相关。

taxonomy。Codex✓ L2+L4。预判失效：锚头集跨底座漂移 / 路由实现与注意力内核耦合。推断

与最接近工作的核心差别：相对 Frame Sink / LongLive sink——本文诊断头分工并在蒸馏期拆路由，而不是推理期统一 sink；相对 dKV（改写）——本文改读上下文路由。

3. dKV Forcing（2611.01648）· 值得读

dKV Forcing（2611.01648）· 值得读

结论 / 对我们： 「生成用的 KV」≠「写入 cache 给未来读的 KV」——应学专用写记忆；SGF 式未来读梯度要用可微 page 单遍算。码未开 → 不升必读·先跑；等 GH 后复评。

白话背景。 SF/CF++ 的梯度在 cache 写入处截断；模型会生成，却没被教「怎么记」。

具体问题。 怎样让未来 chunk 读到的 KV 反传回过去的写操作，又避免可变 cache + checkpoint 炸显存 / 双遍整段图？

方法逐步。

  1. 共享骨干上加 writer-only LoRA residual（只在 cache refresh 启用）。
  2. 训练时用 persistent differentiable pages + 局部 rematerialization，单时间遍历算与双遍重构相同的记忆梯度。
  3. 推理：普通 cache；residual 仅写时开、去噪时关。

为什么。 预训练里写 KV 与生成 KV 已差一大截；替换会伤续写——说明需要独立写表征。

关键数字。原文 相对同目标 SGF：VBench-Long aesthetic +6.6@60s / +8.5@240s；单遍相对双遍 −28% 显存、−20.8% cycle；写梯度开销约 +7% generator update。

限制。【代码】 ZhiqiLi-CG/dKV-Forcing 目前仅 README「Code coming soon」；底座 Causal Forcing++ 1.3B。

taxonomy。Codex✓ L2+L4。预判失效：writer 过强 → 记忆与外观不一致；或 page 实现与 FSDP 难复现。推断

与最接近工作的核心差别：相对 SGF（未来读、双遍）——可微 page 单遍；相对 Commit Forcing（训免改读链）——本文改写表征+训练。
